# Knowledge Base

Reusable patterns and lessons learned from vibe coding projects. Reference these when starting new projects to avoid re-learning the same things.

## Browsing the KB visually

[`kb-browser.html`](./kb-browser.html) is a static, self-contained UI over every lesson below — open it by double-clicking it, no server needed. It gives you:

- **Facets** for `kind` (gotcha / pattern / howto / playbook / architecture / …) and for `stack` tags grouped into Languages, Frameworks & Libraries, Platforms & Runtimes, Cloud & Backend, Data & Sync, Auth & Security, Integrations, Reliability & Perf, and Process & Meta (unrecognized tags fall into "Other" rather than breaking anything).
- **Multi-facet filtering** — selections within a group are OR'd (e.g. Rust *or* TypeScript), selections across groups are AND'd (e.g. Rust *and* Auth & Security).
- **Full-text search**, a **staleness indicator** per the freshness rule below, and sort by recency/title/kind.
- A **detail view** that renders the full lesson (headers, code blocks, tables, lists) via a small built-in markdown renderer.

It's generated, not hand-written. After adding or editing a lesson, regenerate it:

```
python build-kb-browser.py
```

The generator (`build-kb-browser.py`) parses each lesson's frontmatter and pulls its one-liner from this README's Lessons list, then embeds the dataset as JSON into `kb-browser.template.html` to produce `kb-browser.html`. **Edit the template, not the generated file** — `kb-browser.html` gets overwritten every run.

## Agent instructions — copying this into a new project

> **If you are an AI agent (Claude Code or similar)** and the user has told you any of the following:
> - "copy the KB over"
> - "set this project up with the template"
> - "scaffold this with my Claude Code template"
> - "bootstrap this project from the Knowledge Base"
> - or anything semantically equivalent
>
> ...follow this procedure exactly. Do not improvise.

### Step 1 — Confirm target & stack with one question

Ask the user a single question if you don't already know the answer:

> "What stack is this project? (e.g. Tauri + Cloudflare, Next.js, plain CLI, Python, etc.) I'll customize CLAUDE.md and trim work-style rules that don't apply."

If the user already told you the stack, skip the question.

### Step 2 — Copy ONLY the template directory

The template lives at `<KB_ROOT>/claude-project-template/`. The KB root is wherever this `README.md` lives — typically `~/Documents/Vibe Projects/Knowledge Base/` on the original author's machine, but ask the user if you don't know.

Use the user's shell:

- **PowerShell:** `robocopy "<KB_ROOT>/claude-project-template" . /E /XD .git`
- **Git Bash / WSL / macOS / Linux:** `cp -r "<KB_ROOT>/claude-project-template/." .`

**Do NOT copy** the lesson files (`tauri-desktop-oauth.md`, `tauri-ipc-serde.md`, `cloudflare-worker-setup.md`), `DECISIONS.md`, `references.md`, or this README. Those stay in the KB and are only pulled in on demand if relevant to the new project.

### Step 3 — Customize CLAUDE.md

Open `CLAUDE.md` in the new project and:

- Replace `<ProjectName>` with the actual project name everywhere it appears.
- Fill in the "Locked technical decisions" table with the user's answers from Step 1. Delete rows that don't apply (e.g. drop `Payments` for a CLI tool, drop `Frontend` for a backend-only project).
- **Trim stack-irrelevant work-style rules:**
  - **Not a UI project** (CLI, library, backend, infra) → delete the "Mock before you build" row from the Work-style table and remove that section from `docs/WORK_STYLE.md`.
  - **Not a multi-feature app** (single-purpose tool) → leave "Don't reinvent the wheel" alone but consider trimming the "Pause at natural test milestones" section to a one-liner.
- Update the one-line tagline at the top.

### Step 4 — Customize the rest

- Rename `.gitignore.template` → `.gitignore`. Append project-specific ignores under the marked line.
- If the project uses Cloudflare: rename `.mcp.json.template` → `.mcp.json` and follow the inline comments.
- Otherwise: delete `.mcp.json.template` (or leave it for later — it's inert until renamed).
- Prime `docs/CURRENT_STATE.md` with Day-0 placeholders (the file already has TODO markers).
- Leave `docs/HANDOFF_LOG.md` and `docs/CODEBASE_INDEX.md` as-is — they grow at `/end`.

### Step 5 — Verify hooks fire

Critical step. From inside Claude Code in the new project:

1. Ask the user to grant `Write` permission for a one-shot test.
2. Write a throwaway file: `tmp-hook-check.md` with content "delete me."
3. Read `.claude/pending-index-updates.txt`. It should contain `tmp-hook-check.md`.
4. If empty: see "Troubleshooting" in `claude-project-template/README.md`. Most common cause: `CLAUDE_PROJECT_DIR` not set (Python script silently exits).
5. Delete `tmp-hook-check.md` and clear the pending entry.

### Step 6 — Pulling in lessons (later, on demand only)

**Do not auto-load the KB lesson files into context** as part of bootstrap. They live one directory above the template and are deliberately separate.

When the user later starts work that maps to a lesson — e.g. designing OAuth in a Tauri project, setting up a Cloudflare Worker — read the relevant `.md` from the KB root *then*, not now. The lesson frontmatter (`stack:`, `kind:`) helps you decide what's relevant. Lessons are reference material, not auto-loaded context.

### Step 7 — Initial commit

If the new project doesn't have a git repo yet, ask before initializing. Once initialized, make one commit: `Bootstrap project from claude-project-template`. Do not push without explicit user authorization.

- [n-copies-of-truth-drift-guard.md](./n-copies-of-truth-drift-guard.md) — Any app where one "thing" is described in 2+ independent schema copies (DB, sync rules, client schema, shared validators, server write-allowlist, build artifacts) will drift silently. The fix is an automated script that diffs the copies and fails the build — not a checklist. Covers four variants the guard itself cannot catch: a stale clone (internal-consistency checks pass perfectly on stale copies); a "reader" that is secretly a writer (a bootstrap/REST path whose unconditional upsert ERASES columns it never selected); the DEPLOYED copy (a checker that reads the repo tests agreement, not reality — and in CRUD-sync engines one unknown column rejects the whole write and jams the ordered queue behind it, so a single un-deployed file presents as "all sync is broken"); and the WRITE side (a write to a non-authoritative copy is temporary and reverts later, at a distance, looking like a reactivity bug — dev/seed tooling is where it bites). The deployed variant has a nastier sub-case: patch two copies in ONE commit and they are still not synchronised in production, because a cross-language pair ships through two different release mechanics — the commit is the alibi, the staleness splits your users by tier, and the check is a timestamp comparison between the last deploy and the last commit touching that directory.

- [motion-design-token-system.md](./motion-design-token-system.md) — A named easing/duration/preset module (mirrored as CSS vars) so JS and CSS animations can't drift apart, plus a real reduced-motion system: a 4-state preference, bridging into your JS animation library's OWN config (not just CSS), and a universal `!important` kill-switch for hardcoded utility-class durations that bypass the tokens. An easeOut curve spends ~80% of its travel in the first fifth of the duration, so on an opacity 1→0 exit it reads as a snap followed by a hang — "it doesn't fade" and "there's a delay" are one complaint, not two. But the correction is conditional: symmetric is right when the exit IS the animation, front-loaded is right when the user is waiting for what's BEHIND it, so a shared fade flag must carry *why* rather than just whether. - [clip-path-shared-element-morph.md](./clip-path-shared-element-morph.md) — A FLIP-transition variant using a union-bbox + `clip-path` instead of scale-transform (no blurry rescaling), plus a non-obvious gotcha: mixing your animation library's JS interpolator with WAAPI/CSS-transitioned properties in one coupled transition causes visible drift — keep every property on the same thread Also covers the discrete cousin of that bug: a morph's end hand-off (reveal the real element / remove the ghost) scheduled for the same instant by two different mechanisms is a coin-flip between "invisible" and "one-frame hole" — overlap them instead of meeting, and beware softening an invisible snap into a crossfade without checking what the snap was covering. AND the guard that looks sufficient and isn't: `if (!element)` does not catch a DETACHED container — frameworks remove only the outermost host node of an unmounted subtree, `querySelector` traverses detached subtrees perfectly happily, and `getBoundingClientRect` then returns all zeros, flying the transition into the viewport's top-left corner. Top-left = zeroed rect. Check `isConnected` on the node you actually *measure*, at both lookup and commit — and note it presents as intermittent only because which code path you get is selected by your data. ALSO: scoping the reverse-flight lookup with a per-list container attribute and rendering `null` when the list is empty are MUTUALLY EXCLUSIVE — the scope is what promotes a dormant early-return into a live detached-container bug, so both fixes must land together; and making the *section* permanent is not enough, because the node carrying the attribute is the one that must never unmount.

- [derive-dont-track-ui-flags.md](./derive-dont-track-ui-flags.md) — A boolean UI flag with more than a couple of reset paths (back button, Escape, nav-away, races...) will eventually get stuck true on the path someone forgot. Fix: derive it from state that's already correctly maintained, eliminating the reset action entirely. Same shape applies in the DATABASE: store when a rule was established and invalidation becomes a WHERE clause, deleting the listeners, the cleanup job and the race — and it works retroactively and across devices.
- [tombstone-vs-hide-for-mirrored-data.md](./tombstone-vs-hide-for-mirrored-data.md) — A soft-delete tombstone claims "this shouldn't exist anywhere" — false for rows mirrored from an external authority (Steam library, calendar sync) that the server deliberately keeps live. Use a local-only, non-syncing hidden flag instead; soft-deleting re-derivable data is an unwinnable fight against a correctly-functioning sync engine. Plus two guard rules for genuine deletes: write-throughs must never re-insert a tombstoned row, and tombstone GC must be replication-confirmed, not a bare wall-clock timer.
- [dry-modularity-audit-playbook.md](./dry-modularity-audit-playbook.md) — Sibling to the security audit playbook: fan out read-only sweeps by code AREA (not trust domain), tier findings by drift-risk (already-bit-us / worthwhile / opportunistic) instead of line count, keep file-split candidates as a separate list, execute tier-by-tier as traceable separate commits.
- [byo-api-key-client-direct-tier.md](./byo-api-key-client-direct-tier.md) — Let users paste their own API key and call a metered third-party API directly instead of through your server, for a genuine free tier. The client-direct call must run from native code (key custody + CORS), one low branch point forks the network call only, one predicate per capability (never widen a shared "isPremium"), and a free key's real rate limit needs its own concurrency/retry tuning, not the paid path's. Getting the predicates right is only half of it: audit the OFFERS as well as the gates — a capability correctly open to BYO users was advertised only on a subscription edge, so a whole tier had it and was never told.
- [local-sqlite-app-wide-change-signal.md](./local-sqlite-app-wide-change-signal.md) — A local DB with no live-query layer needs ONE coalesced "data changed" signal with every write choke point as a producer, or writers outside the original ad hoc poke inventory (a second window, a background sync engine) go stale with zero errors. Includes a debugging trap: verify data actually reached the layer before assuming the missing piece is the signal itself.
- [windows-crash-reporter-child-busy-cursor.md](./windows-crash-reporter-child-busy-cursor.md) — **Dead-end article (no fix on stable Rust).** Out-of-process minidump capture re-executes your binary as a windowless GUI-subsystem child, so Windows spins the busy cursor ~5s on every launch while the app sits idle and responsive. Identify it in 10 minutes (count processes in Task Manager; build release *unsigned* to exonerate Authenticode); `STARTF_FORCEOFFFEEDBACK` is the industry fix but is unreachable from `std::process::Command` on stable (`creation_flags()` is a decoy — different field); an early `PeekMessage` in the child is **measured** not to work. Pragmatic call: disable the minidump lane, keep the panic/JS lanes that actually catch bugs.
- [azure-cli-windows-auth-traps.md](./azure-cli-windows-auth-traps.md) — Re-authenticating `az` on Windows hides three stacked traps: the prompt is a native WAM dialog, not a browser (so "nothing opened" and `BROWSER` overrides are ignored — `az config set core.enable_broker_on_windows=false` restores the browser flow); device-code flow gets blocked with AADSTS530035 days after tenant creation when Microsoft auto-enables security defaults ("it worked two days ago" is true and useless); and the picker pre-offers the personal Microsoft account, whose failure text ("add as an external user") reads like broken setup but just means wrong-account-clicked. Pre-flight any signing pipeline with a 2-second `az account get-access-token --scope …codesigning…` so an expired token can't hang the build at `Signing …`.
- [r2-presigned-put-size-limits.md](./r2-presigned-put-size-limits.md) — Community consensus says R2 presigned PUTs can't bound upload size (S3's `content-length-range` POST policy doesn't exist on R2) — measured false: R2 DOES verify signed `Content-Length`/`Content-Type` on a query-signed PUT (mismatch → 403 before bytes land). The trap: aws4fetch's default treats both as *unsignable* and silently drops them from the signature, so the limit ships decorative and even passes naive testing. Fix is `aws: { allHeaders: true }`; protocol is "read `X-Amz-SignedHeaders` in the URL you minted, and test the MISMATCH case, not the match case."
- [db-backed-auth-503-not-401.md](./db-backed-auth-503-not-401.md) — When session verification moves from stateless (JWT signature) to stateful (opaque token in a sessions table), "verify threw" gains a second meaning: the catch-all `→ 401` that was safe for a JWT now converts a DB blip into a mass "everyone got signed out" incident. Tag store failures `transient` in the verifier, map them to 503 in EVERY http-facing caller (audit the copy-pasted inline guards), and keep the client tri-state (`valid/invalid/unreachable`) where only a literal 401 tears down session state. Applies to any auth check that does I/O (Redis sessions, OIDC introspection, entitlement gates).
- [session-revocation-vs-minted-tokens.md](./session-revocation-vs-minted-tokens.md) — Opaque revocable sessions give you instant "sign out everywhere", but any short-lived token you MINT from a session and hand to a stateless verifier (PowerSync/JWKS JWTs, S3/R2 presigned URLs, access tokens) outlives the revoke by its own TTL — there's no revocation list in the JWKS/presigned model. Close the gap by routing high-value actions (writes, minting NEW tokens) through the revocable session so they 401 instantly, keep minted-token TTLs short (that TTL = your revocation latency), and skip the real-time force-logout push (it only shaves a read-only tail on a device that already holds the local copy). "Signed out" is a per-request server check, not a client state.
- [tauri-sentry-debug-id-envelope-drop.md](./tauri-sentry-debug-id-envelope-drop.md) — Turning ON source-map symbolication silently deletes 100% of your JS error reports in a Tauri app: `@sentry/vite-plugin` injects debug IDs → `@sentry/browser` attaches a `debug_meta` image of `type: "sourcemap"` → `sentry-types`' closed `DebugImage` enum has no such variant → `Envelope::from_slice` fails → `tauri-plugin-sentry`'s `if let Ok(...)` (no `else`) drops the envelope with zero diagnostics, while Rust panics keep flowing so the dashboard looks alive. Ten-minute identification checklist (the decisive test: deliberate Rust panic vs JS error — if only one lane lands, it's the JS→native boundary), the vendored-crate fix with the two serde traps (`rename = "sourcemap"` not snake_case; keep every field `Option<String>` so the fix can't reintroduce a strict-parse drop), and the general rule that `if let Ok(x) = parse(...)` at any boundary is a silent data destroyer.
- [signed-but-flagged-download-reputation.md](./signed-but-flagged-download-reputation.md) — A correctly code-signed Windows installer (`signtool verify /pa` clean, VirusTotal 0/N) still trips Chrome "isn't commonly downloaded" and SmartScreen "Windows protected your PC" because both are REPUTATION systems (download volume + signing identity + file hash), not signature checks. 2026 traps for Azure Trusted Signing: the EV-cert instant-reputation escape hatch is gone, and a ~late-March-2026 CA migration (`AOC CA 0x` intermediates) reset SmartScreen rep. The soft Chrome notice has NO appeal (the Safe Browsing report form is only for false _dangerous_ verdicts) — it clears with volume under a stable identity. VirusTotal 0/N doesn't clear it but is a reassurance artifact to link (re-scan per build; hash is per-version).
- [write-triggered-enforcement-blind-to-deletion.md](./write-triggered-enforcement-blind-to-deletion.md) — A `PostToolUse`-style hook that fires on "file written" guarantees every NEW file gets a docs/index row, and is structurally blind to a row being DELETED — so a cleanup commit that removed a contiguous block (correctly finding its 4 phantom rows, silently taking 3 live neighbours) left a 643-line core file undiscoverable for 3.5 weeks with zero downstream signal. Includes the selection effect that makes it worse (most rows self-heal when the file is next touched, so the ones that STAY missing are the stable, load-bearing ones), the false-"all clear" regex trap when writing the verification scan (match the first table column only, not paths mentioned in neighbouring prose), and the one-second invariant check that replaces it. General rule: enforce invariants, not events — and ask of every hook, "what happens when someone deletes?"
- [always-on-top-overlay-vs-exclusive-fullscreen.md](./always-on-top-overlay-vs-exclusive-fullscreen.md) — An always-on-top window can't out-paint an exclusive-fullscreen game but STILL wins hit-tests from the z-order: an invisible click-eater whose stolen focus minimizes the game (and whose hover-paused auto-dismiss never fires). Painting and input routing are separate systems. Fix is to bow out like Windows' own toasts do — `SHQueryUserNotificationState`, treating only `QUNS_RUNNING_D3D_FULL_SCREEN` as exclusive (borderless reports `QUNS_BUSY` and composites fine) — checked at fire time AND via a lifetime watcher (launcher-first games claim the display AFTER your window opens). Why click-through and more-topmost-flags are dead ends; disclose the limitation in settings.
- [pushstate-overlay-history-drift.md](./pushstate-overlay-history-drift.md) — SPAs that dismiss overlays via pushState/popstate drift the stack from the UI two ways: `history.state` survives reloads (base entry reboots claiming an overlay is open → anti-double-push guard skips → `history.back()` is a SILENT no-op → dead Back button; prod-real in browsers where F5 is a habit), and closes that bypass history orphan their entries (multi-click Back). Four-piece cure: boot `replaceState(null)`, a self-sufficient Back handler that only trusts a stack that actually has a poppable entry, consume entries on direct closes, make close-of-nothing a no-op. Plus the caveat that some orphaned entries are deliberate flow features — consume selectively.
- [patch-the-consumer-not-the-value.md](./patch-the-consumer-not-the-value.md) — Changing behavior in a compiled artifact you can't rebuild: the published technique is always "find the constant and overwrite it," which silently fails whenever the binary CONSUMES the value rather than originating it (engine + asset pack, app + remote config) — here the real value lived in an 18.5 GB asset pack, not the 78 MB exe. Patch the branch that reads it instead: source-agnostic, and a length-preserving `test r/m8, 1` → `test r/m8, 0` beats rewriting `je`→`jmp` (no displacement math). Plus: mine the `.pdb`/`.map`/sourcemap that shipped by accident (S_PUB32 records give exact addresses in ~40 lines), cross-validate the site two independent ways before writing a byte, and distribute by uniqueness-measured signature scan (9 matches bare vs 1 with context) that refuses to write on ≠1 match — never a hardcoded offset.
- [single-select-that-commits-cant-be-a-radio-group.md](./single-select-that-commits-cant-be-a-radio-group.md) — A native radio group SELECTS as the arrow keys travel through it, and that selection dispatches both `change` AND `click` — so no event on a radio distinguishes "chose this" from "passed over this on the way elsewhere". Any control that commits, writes, closes or navigates on selection therefore fires that on values the user never picked (measured: guarding on `click` does not help; `event.detail` is reasoned-and-rejected, label-forwarded clicks make it unreliable and it breaks Space). Radios use *automatic* activation and offer no browse-without-selecting state — which is exactly the "arrows move, Enter confirms" model people describe wanting. Fix: buttons + `aria-pressed` (five tab stops, which is what users assume anyway), or the ARIA manual-activation pattern if you need one tab stop. Radios stay correct wherever selection is cheap and reversible, e.g. inside a form that commits on Save.
- [chase-industry-stats-to-a-primary-source.md](./chase-industry-stats-to-a-primary-source.md) — Confident industry numbers often trace to nothing: vendor marketing copy citing vendor marketing copy. Worked example + **negative result** — no published days-lapsed→return-probability curve for games exists in public sources (searched the ten vendors who would hold it; the ones with data gate it). The real peer-reviewed 9–14 day convergence is a churn-PREDICTION threshold tuned against false positives, i.e. when a player stops being worth money, not when they'd enjoy returning — a swap that had already reached a code constant's justifying comment. Three-tier labelling (hard data / design convention / opinion), the reference-class check that survives a valid citation, and what to do when nothing survives: argue from ASYMMETRY OF ERROR using your own system (which direction is free?) rather than a borrowed number.
- [bot-challenge-blocks-your-auto-updater.md](./bot-challenge-blocks-your-auto-updater.md) — Put an update manifest behind Cloudflare and it serves browsers fine while 403-ing `reqwest`, curl's default and empty user-agents, so auto-update can be dead for every user while the download page works — and because updater check-failures are deliberately silent, nobody reports it. Includes why BOTH obvious tests lie (curl's own UA is a blocked signature; a browser UA proves nothing you shipped), how to read the real UA out of the dependency source, a measured UA/status table, the 200-with-HTML variant that fails in your JSON parser instead of the transport, and why passing today is an accident you're depending on rather than a decision anyone made.
- [local-fixture-reverts-under-authoritative-sync.md](./local-fixture-reverts-under-authoritative-sync.md) — Your "seed test data" / "backdate this record" debug button writes locally, the UI renders it, and it evaporates seconds later because the sync engine upserts the server's row back down. The diagnostic is that it reverts **partially** — server-owned columns snap back, client-owned ones survive — which is proof of mechanism and also hands you the fix. Plus the trap that cost the most: a suppression flag existed, was correctly named and documented, and guarded a different sync path than the one doing the damage, which is worse than no flag at all.
- [two-surfaces-split-only-by-a-threshold.md](./two-surfaces-split-only-by-a-threshold.md) — "Recent here, older there" is one list with a seam: the predicates overlap near the boundary so removing an item from one feed doesn't remove it (the button visibly does nothing), and items migrate between surfaces on their own as time passes, spending location — a strong memory cue — on a value the user isn't tracking. Divide by what EVIDENCE you have about an item instead, so transitions between surfaces are caused rather than scheduled; time then becomes a knob inside one surface. Includes the three-question test to apply before adding any surface.

- [tauri-updater-key-passphrase-without-stranding.md](./tauri-updater-key-passphrase-without-stranding.md) — The Tauri updater secret key is usually passphrase-less, which makes reading one file equal to silent-RCE power over every install — and the reflex fix (regenerate with a password) STRANDS the whole install base because the pubkey is compiled into shipped binaries. Same-keypair rekey instead: the key file is base64 of a standard minisign secret key, so decode → `minisign -C` → re-encode, then a three-step verify (empty password must FAIL, passphrase signs via the release pipeline's exact env channel, signature verifies against the SHIPPED pubkey). Includes the measured non-repro of tauri#13485 on CLI 2.10.1, the fail-fast test-sign pattern for release scripts, and the backup-rotation hunt (password-manager version history, sync-client recycle bins, disk scan beats memory).
- [powershell-51-utf8-no-bom-string-breakage.md](./powershell-51-utf8-no-bom-string-breakage.md) — Windows PowerShell 5.1 decodes BOM-less UTF-8 scripts as cp1252, and a UTF-8 em-dash's middle bytes include 0x94 = a curly double-quote the parser accepts as a REAL string delimiter — so smart punctuation can close a string early and turn message text into parsed code ("The term 'exit' is not recognized" pointing inside a string literal). Keep .ps1 ASCII or UTF-8-with-BOM. Plus the adjacent trap: JSON `\uXXXX` escapes in agent tool-call params decode to literal control bytes before reaching disk — build the backslash from a char code when a file needs the escape TEXT.
- [suspect-the-statistic-before-the-threshold.md](./suspect-the-statistic-before-the-threshold.md) — A `if measure(x) < T` rule has two places to be wrong, and the threshold is the seductive one. When it misfires on a LARGE FRACTION of inputs, the measure is the bug and no cut point can save you. Measured: a "too dark to see?" check misclassified 86 of 419 logos via two compounding flaws — luma underrates saturated colour (pure blue scores 29), and a mean gets eaten by anti-aliasing and glow (one logo: mean 53, actual mark 204). Fix: max-channel, high percentile, restricted population. Includes the one-minute diagnostic and the non-image analogues (p50 latency, average session length, overall accuracy).
